Architektur – KI-Integration

Projekt: AI Process Designer  |  Hochschule Ruhr West – Master Informatik  |  Stand: Mai 2026

1. Überblick

Der AI Process Designer ist ein Low-Code-Frontend zur visuellen Modellierung von KI-gestützten Entscheidungs- und Analyseprozessen. Die KI-Integration besteht aus zwei Teilen:

  1. KI-Assistent (ChatPanel) – ein konversationeller Assistent, der natürlichsprachliche Beschreibungen in ausführbare XML-Prozessdefinitionen übersetzt.
  2. Provider-Abstraktion – eine austauschbare Schicht, die es erlaubt das zugrundeliegende Sprachmodell (LLM) ohne Codeänderungen zu wechseln.
Kernprinzip: Das System ist modellunabhängig. Jeder LLM-Anbieter der die OpenAI-Chat-Completions-API implementiert – darunter OpenAI, Azure OpenAI und lokale Modelle über Ollama – kann ohne Änderung an der Kernlogik verwendet werden.

3. Schichtenmodell der KI-Integration

3.1 Schicht 1 – Typen und Interfaces (src/lib/ai/types.ts)

Definiert die Verträge zwischen den Komponenten:

Interface / TypBeschreibung
AIProviderVertrag für alle LLM-Provider: eine einzige Methode chat(messages[])
AIConfigLaufzeit-Konfiguration: baseUrl, apiKey, model
ChatMessageEinzelne Nachricht im Gesprächsverlauf: role + content
interface AIProvider {
  chat(messages: ChatMessage[]): Promise<string>;
}

interface AIConfig {
  baseUrl: string;   // z.B. https://api.openai.com/v1
  apiKey:  string;
  model:   string;
}

interface ChatMessage {
  role: "user" | "assistant" | "system";
  content: string;
}

3.2 Schicht 2 – Provider-Implementierung (src/lib/ai/providers/openai-compat.ts)

Die Klasse OpenAICompatProvider implementiert AIProvider und spricht jeden Endpunkt an, der das OpenAI Chat-Completions-Format unterstützt:

  • Verwendet natives fetch() – kein zusätzliches SDK-Paket nötig
  • Sendet POST {baseUrl}/chat/completions mit Authorization: Bearer {apiKey}
  • Liefert sprechende Fehlermeldungen bei 401 Unauthorized, 404 Not Found und Verbindungsfehlern
  • Funktioniert unverändert für OpenAI, Ollama und jede weitere OpenAI-kompatible API

3.3 Schicht 3 – Factory und Konfigurationsauflösung (src/lib/ai/index.ts)

Zwei exportierte Funktionen verbinden Konfiguration und Provider:

FunktionAufgabe
resolveConfig(meta?)Ermittelt die aktive Konfiguration nach Priorität (siehe Abschnitt 4)
createProvider(config)Factory-Funktion – gibt die passende Provider-Instanz zurück
Erweiterbarkeit: Um einen neuen Provider (z.B. Anthropic Claude, Google Gemini) hinzuzufügen, genügt es eine neue Klasse zu erstellen die AIProvider implementiert, und createProvider() um einen neuen Zweig zu erweitern. Alle übergeordneten Schichten bleiben unverändert.

4. Konfigurationssystem

Die Konfiguration des LLM-Providers folgt einer dreistufigen Priorität:

PrioritätQuelleAnwendungsfall
1 (höchste)ProcessMeta.llmHost / ProcessMeta.modelProzess-spezifisches Modell – im ProcessSettingsPanel konfiguriert, wird im XML gespeichert
2VITE_AI_BASE_URL / VITE_AI_MODEL / VITE_AI_API_KEYAnwendungsweiter Standard in .env.local
3 (Fallback)Hartkodierte Standardwertehttps://api.openai.com/v1, Modell gpt-4o-mini

Umgebungsvariablen (.env.local)

# Ollama (lokal)
VITE_AI_BASE_URL=http://localhost:11434/v1
VITE_AI_API_KEY=ollama
VITE_AI_MODEL=qwen2.5:7b

# OpenAI
# VITE_AI_BASE_URL=https://api.openai.com/v1
# VITE_AI_API_KEY=sk-...
# VITE_AI_MODEL=gpt-4o-mini

Sicherheitshinweis: Die Datei .env.local ist in .gitignore aufgenommen (*.local) und wird nicht in das Repository eingecheckt. Die Datei .env.example dient als Vorlage ohne sensitive Werte.

5. KI-Assistent (ChatPanel)

5.1 Funktionsweise

Das ChatPanel (src/components/process-designer/ChatPanel.tsx) ist die Benutzeroberfläche des KI-Assistenten und übernimmt folgende Aufgaben:

  1. Gesprächsverwaltung: Der vollständige Gesprächsverlauf wird in einem useRef als ChatMessage[] gehalten und bei jedem API-Aufruf als Kontext mitgesendet – das Modell „erinnert" sich an frühere Nachrichten.
  2. System-Prompt: Beim ersten Aufruf wird ein fester System-Prompt mitgesendet, der das Modell auf die Rolle als XML-Prozess-Generator einstellt, das XML-Format erklärt und anweist, Variablen und Container selbstständig aus der Nutzerbeschreibung abzuleiten.
  3. XML-Extraktion: Die Funktion extractXml() erkennt XML im LLM-Output in zwei Formaten:
    • Als Markdown-Codeblock: ```xml ... ```
    • Als rohes XML direkt im Text: <process>...</process>
    Das erkannte XML wird aus dem Anzeigetext entfernt und separat gespeichert.
  4. Import in den Designer: Der Button „Als Graph übernehmen" übergibt das extrahierte XML an parseProcessXml(), welches daraus ReactFlow-Nodes und -Edges erzeugt. Fehler beim Parsen werden als Chat-Nachricht angezeigt.
  5. Modell-Wechsel: Beim Start lädt das Panel die verfügbaren Modelle vom Provider-Endpunkt (GET {baseUrl}/models) und zeigt sie in einem Dropdown an. Die Auswahl aktualisiert ProcessMeta.model.

6. Prozesskatalog

Der Prozesskatalog ermöglicht das Speichern und Wiederverwenden von Prozessdefinitionen:

KomponenteDateiAufgabe
CatalogEntrytypes.tsDatentyp: id, name, xml, createdAt
useCatalog()src/lib/useCatalog.tsReact-Hook: liest/schreibt Einträge in localStorage (Key: process-catalog)
SidebarSidebar.tsxZeigt gespeicherte Prozesse an, ermöglicht Laden und Löschen
Speichern-ButtonDesigner.tsxSpeichert aktuellen Prozessname + XML in den Katalog (Upsert nach Name)

Die Persistierung erfolgt ausschließlich im Browser-localStorage. Eine serverseitige Persistierung (Datenbank, REST-API) ist als zukünftige Erweiterung vorgesehen.

9. Erweiterungsmöglichkeiten

  • Streaming-Antworten: Erweiterung des AIProvider-Interface um eine optionale stream()-Methode für Echtzeit-Textausgabe
  • Weitere Provider: Neue Klassen (z.B. AnthropicProvider, GeminiProvider) die AIProvider implementieren, ohne bestehenden Code zu ändern
  • Prozessausführung: Nutzung der gleichen Provider-Schicht um die einzelnen Steps eines modellierten Prozesses tatsächlich auszuführen
  • Serverseitige Persistierung: Ersetzen von localStorage durch eine REST-API mit Datenbankanbindung
  • Authentifizierung: Backend-Proxy der API-Keys serverseitig hält, statt sie im Browser zu speichern
